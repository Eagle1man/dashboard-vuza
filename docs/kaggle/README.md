# Дообучение модели на знаниях мониторинга: что это даёт и чего не даёт

Документ отвечает на задачу «обучить небольшую модель 14B в Kaggle, чтобы
она отлично владела знаниями мониторинга». Здесь честно разделено: что
дообучение действительно решает, а что решается базой знаний (RAG) и
почему для цифр второе важнее.

---

## 1. Главное: знания — не то, что вшивают в веса

Цифры мониторинга меняются каждый год: в 2024 году у вуза один средний
балл ЕГЭ, в 2025 — другой, в 2026 придёт третий. Если «вшить» их в веса:

- модель **не сможет ответить «не знаю»** — она будет выдавать числа
  из обучающего текста даже когда данные устарели;
- проверить, откуда взялось число, невозможно: в весах нет ссылки на
  источник, а именно этого требует наш `grounding.py`;
- обновление данных = новое обучение, то есть каждый год заново.

Поэтому цифры остаются в базе знаний: сегодня это
`knowledge/official/monitoring/` (57 детальных показателей за 2024 и
2025 годы, полные таблицы по 37–38 вузам Ростовской области). Ассистент
достаёт нужный фрагмент и отвечает с источником.

## 2. Что дообучение реально улучшает

| Задача | Даёт ли QLoRA |
|---|---|
| Стиль ответа: коротко, по-русски, с источником | **да**, заметно |
| Отказ вида «в документах этого нет» вместо выдумки | **да**, если в датасете есть такие примеры |
| Понимание структуры наших документов (E.1…E.8, места, медианы) | **да, частично** |
| Знание конкретных чисел за 2024/2025 | **нет**: устареет и не проверяется |
| Арифметика и сравнение чисел | **нет**: это работа кода, а не модели |

Вывод: дообучение — про **поведение**, а не про **память**. Для
«отлично владеет знаниями» правильная связка: RAG отдаёт факты, LoRA
учит, как с этими фактами обращаться.

## 3. Что нужно для Kaggle

| Параметр | Значение |
|---|---|
| Модель | `unsloth/Qwen2.5-14B-Instruct-bnb-4bit` (4 бита, ~8,5 ГБ) |
| Метод | QLoRA: r=16, alpha=32, dropout=0.05 |
| Железо | Kaggle T4×2 (16 ГБ на GPU) или P100 |
| Время | 3–6 часов на 1–2 эпохи, лимит сессии 12 часов |
| Датасет | 800–2000 пар «вопрос → ответ по фрагменту» |
| Экспорт | merge LoRA → GGUF `q4_k_m` (~9 ГБ), скачать, `ollama create` |

Квота Kaggle — около 30 часов GPU в неделю; одна попытка укладывается.

## 4. Датасет: откуда брать пары

Плохой путь — «скормить модели весь текст». Тогда она выучит числа
наизусть и разучится говорить «не знаю».

Правильный путь — пары, где ответ **выводится из фрагмента**:

```
Вопрос: Какое место занимает ИУБиП по объёму НИОКР среди вузов области в 2025?
Контекст: [фрагмент region-2025.md, раздел E.2]
Ответ: 5-е место из 38. Значение — 419,85 тыс. руб. на одного НПР.
Источник: monitoring.miccedu.ru, выпуск 2025.
```

Плюс обязательные примеры-отказы:

```
Вопрос: Сколько студентов в ИУБиП в 2027 году?
Контекст: [фрагменты без этого года]
Ответ: В документах нет данных за 2027 год. Последнее, что есть — выпуск
мониторинга 2025 года (данные за 2024).
```

Скрипт `docs/kaggle/dataset_build.py` собирает такие пары из нашей базы:
шаблоны вопросов по каждому показателю, ответ — из соответствующей строки
markdown. Это не «идеальный» датасет, но он учит формат и отказы, а не
запоминание.

## 5. Порядок работ

1. `python docs/kaggle/dataset_build.py` — собрать `train.jsonl`.
2. Загрузить `train.jsonl` в Kaggle как Dataset.
3. Открыть `docs/kaggle/finetune_qwen14b.ipynb`, включить GPU T4×2, Run all.
4. Скачать получившийся GGUF (~9 ГБ) из `/kaggle/working`.
5. На сервере: `ollama create rector-qwen -f Modelfile`, затем
   `python -m backend.models small rector-qwen`.
6. Прогнать `python -m backend.smoke --ask "..."` и сравнить с базовой
   моделью по тем же вопросам.

## 6. Чего ждать по скорости

Наша ВМ считает без AVX2: 2,4 ток/с на плотной 14B. Дообученная модель
будет той же архитектуры, то есть **такой же медленной**. Дообучение не
ускоряет инференс. Если нужна скорость — это AVX2 на гипервизоре или GPU,
а не LoRA.

## 7. Альтернатива, которая даёт больше за меньшие деньги

Прежде чем тратить 6 часов GPU, стоит проверить, где именно RAG
ошибается:

- **реранкер** (`Qwen3-Reranker-0.6B`) — переставляет найденные фрагменты,
  чтобы в промпт попадали лучшие;
- **нарезка по заголовкам**: сейчас региональные таблицы режутся по 400
  токенов и рвут строку «вуз — значение»;
- **перефразирование вопроса** перед поиском.

Эти три вещи обычно дают больше, чем LoRA, и не требуют обучения.
