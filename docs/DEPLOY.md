# Развёртывание дашборда ректора

Документ для того, кто ставит систему на машину и пускает людей.
Рассчитан на 2–4 часа работы, если машина уже есть и есть интернет для
скачивания моделей.

---

## 1. Что получится в итоге

- Веб-страница `http://<адрес-машины>:8765/` — витрина показателей.
- `/upload.html` — загрузка файлов подразделениями: PDF, DOCX, XLSX,
  CSV, TXT, MD, HTML.
- `/review.html` — проверка карточки и публикация загруженного.
- ИИ-ассистент в правом нижнем углу дашборда: отвечает по загруженным
  документам со ссылками на файл и раздел.
- Всё локально: ни документы, ни вопросы никуда не уходят.

## 2. Требования к машине

| Что | Минимум | Комфортно |
|---|---|---|
| ОЗУ | 8 ГБ (модель 1.5B) | 16 ГБ (модель 7B), 24 ГБ (14B) |
| Процессор | 4 ядра | 8 ядер и больше |
| Диск | 5 ГБ | 20 ГБ (модели + документы + бэкапы) |
| ОС | Windows 10/11, Ubuntu 22.04/24.04 | — |
| Сеть | интернет при установке (скачать модели) | — |

Видеокарта не обязательна. С ней ответы в разы быстрее, без неё
1.5B отвечает 1–3 минуты, 7B — 2–5 минут на вопрос.

## 3. Установка: Windows

Время: 20–40 минут, из них 10–20 — скачивание моделей.

1. Поставить Python 3.10+ с <https://www.python.org/downloads/>,
   отметив **Add Python to PATH**.
2. Поставить Ollama с <https://ollama.com/download> и запустить её.
3. Скачать модели (в командной строке):
   ```
   ollama pull qwen2.5:1.5b
   ollama pull nomic-embed-text
   ```
4. В папке проекта запустить `install.bat` — он создаст `.venv`,
   поставит зависимости, выберет модель по железу и построит индекс.
5. Запустить `start.bat`. Откроется браузер с дашбордом.
6. Проверить готовность:
   ```
   .venv\Scripts\python.exe -m backend.smoke
   ```

**Автозапуск после перезагрузки** (запускать PowerShell от админа):
```
powershell -ExecutionPolicy Bypass -File deploy\windows\service-install.ps1
```
Скрипт создаёт задачу Планировщика `RectorDashboard`, правило
брандмауэра на порт 8765 и запускает сервер. Журнал:
`logs\server.log`. Удалить автозапуск: `service-remove.ps1`.

## 4. Установка: Ubuntu

Время: 20–40 минут.

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip curl
curl -fsSL https://ollama.com/install.sh | sh
sudo systemctl enable --now ollama
ollama pull qwen2.5:1.5b
ollama pull nomic-embed-text

git clone <адрес-репозитория> /opt/rector-dashboard
cd /opt/rector-dashboard
./install.sh
```

Запуск вручную: `./start.sh`.
Автозапуск службой — см. `deploy/systemd/README.md`:

```bash
sudo cp deploy/systemd/rector-dashboard.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now rector-dashboard
```

## 5. Открыть для сети

По умолчанию сервер слушает только себя (`127.0.0.1`) — с других машин
он недоступен. Чтобы пустить людей:

| Платформа | Что сделать |
|---|---|
| Windows | `service-install.ps1` уже ставит `RECTOR_API_HOST=0.0.0.0` и правило брандмауэра |
| Ubuntu | в `rector-dashboard.service` уже стоит `RECTOR_API_HOST=0.0.0.0`; открыть порт: `sudo ufw allow 8765/tcp` |
| Ручной запуск | `set RECTOR_API_HOST=0.0.0.0` (Windows) или `export RECTOR_API_HOST=0.0.0.0` (Linux) |

**Обязательно вместе с этим:** `RECTOR_REQUIRE_LOGIN=1`. Иначе витрину,
документы и чат увидит любой в сети без входа. В службах это уже
включено; при ручном запуске задайте переменную сами.

Проверить с другой машины: `http://<ip-сервера>:8765/`.

## 6. Пароли и подразделения

При первом запуске создаются 21 учётная запись: `admin` и подразделения
(`buhgalteria`, `umo`, `admission` и т.д.). Пароли **случайные** и
записаны один раз в `data/initial_passwords.txt`.

```
python -m backend.users list                 кто есть
python -m backend.users passwd admin         сменить пароль (спросит дважды)
python -m backend.users passwd umo --random  сгенерировать и напечатать
```

После того как пароли розданы — **удалите `data/initial_passwords.txt`**.
Проверка `backend.smoke` предупреждает, пока файл лежит на месте.

Если база осталась от прежней версии (пароль совпадал с логином),
`smoke` покажет список таких учёток — смените их тем же `passwd`.

## 7. Проверка готовности

Одна команда отвечает «можно пускать людей или нет»:

```
python -m backend.smoke
python -m backend.smoke --ask "вопрос по вашим документам"
```

Что проверяется: Python, база и корпус, векторы (не аварийная ли
заглушка), слабые пароли, Ollama, обе модели, ответ сервера. Живой
вопрос дополнительно убеждается, что модель ответила и вернула
источники.

Код возврата 0 — можно работать; 1 — есть блокирующая проблема, она
напечатана в конце.

## 8. Первый рабочий день: как грузить данные

1. Сотрудник заходит на `/index.html` под своим логином.
2. `/upload.html`: выбирает файл, заполняет анкету (что это, период,
   ответственный), отправляет.
3. Система разбирает файл, строит карточку показателей и запускает
   проверки. Файл к этому моменту уже сохранён в
   `knowledge/<подразделение>/<год>/` и доступен ассистенту.
4. `/review.html`: проверяющий смотрит карточку и сырые строки,
   при необходимости правит и нажимает «Опубликовать». Публикация
   переносит значения в витрину с провенансом (кто, когда, из какого
   файла).
5. Ассистент отвечает по опубликованным и загруженным документам.

Без публикации значения в витрину не попадут, но текст документа
ассистент уже видит — это осознанно: вопрос «что написано в приказе»
не должен ждать бухгалтерии.

## 9. Обслуживание

| Задача | Команда |
|---|---|
| Резервная копия | `backup.bat` (Windows) или копия `data/dashboard.db` |
| Переиндексация после правки `knowledge/` | `python -m backend.ingest --prune` |
| Полный пересчёт векторов | `python -m backend.ingest --force` |
| Обновление кода | `git pull`, затем перезапуск службы |
| Журнал действий | `/journal.html` или `/api/journal/export/csv` |

Бэкап делать при остановленном сервере или сразу после `--prune`:
SQLite в режиме WAL иначе требует ещё файлов `-wal` и `-shm`.

## 10. Модели

```
python -m backend.models                  что сейчас на ролях
python -m backend.models list             что скачано
python -m backend.models small qwen2.5:7b сменить основную модель
python -m backend.models large qwen2.5:14b сменить модель объяснений
python -m backend.models auto small       вернуть автовыбор
```

- Смена модели не требует перезапуска и пересчёта индекса.
- Большая модель на процессоре отвечает минутами: поднимите
  `RECTOR_OLLAMA_TIMEOUT` (в службах уже 600 с).
- 7B и больше ставить на машине с 16 ГБ ОЗУ и выше.

## 11. Если что-то не работает

| Симптом | Причина и лечение |
|---|---|
| «Модель недоступна» в панели ассистента | Ollama не запущена или занята загрузкой модели. `systemctl status ollama` / перезапустить Ollama |
| «Модель не скачана» | `ollama pull <модель>` — точное имя в `python -m backend.models` |
| Ответ «сводный ответ недоступен: timed out» | модель не успела. Поднять `RECTOR_OLLAMA_TIMEOUT` или взять модель поменьше |
| Ассистент не находит документ | он ещё не в индексе: `python -m backend.ingest --prune` |
| С других машин страница не открывается | `RECTOR_API_HOST` остался `127.0.0.1` либо закрыт порт в брандмауэре |
| Вход не принимается | пароль из `data/initial_passwords.txt`; после 5 неудач вход блокируется на 15 минут |
| Страница показывает старый интерфейс | Ctrl+F5; сервер отдаёт `no-cache`, но прокси мог закэшировать |

## 12. Честные ограничения

Это важно сказать тем, кто будет пользоваться, до первого вопроса:

- Ассистент отвечает **по загруженным документам**, и ответ проходит
  автоматическую проверку: предложения с числами, которых нет в
  найденных фрагментах, удаляются, ссылки на несуществующие фрагменты
  снимаются, повторы одного пункта схлопываются. Под ответом печатается
  замечание проверки — что именно убрано. Если убрать пришлось всё,
  вместо ответа показываются найденные фрагменты.
  Это защита от выдуманных чисел, но **не гарантия полноты**: проверка
  не доказывает, что оставшиеся утверждения — единственно верные.
  Для отчётности используйте витрину и провенанс.
- На модели 1.5B качество пересказа заметно ниже, чем на 7B. 1.5B
  выбрана ради скорости на слабом железе.
- Один сервер = одна база. Параллельная работа десятков пользователей
  упрётся в процессор на этапе генерации ответа: модель отвечает по
  одному вопросу за раз.
- Демонстрационные документы помечены в интерфейсе. Перед боевым
  запуском удалите папку `knowledge/demo`, если она есть, и выполните
  `python -m backend.ingest --prune`.

## 13. План на 20 часов

| Часы | Что делается | Кто |
|---|---|---|
| 1–2 | выбрать машину, поставить ОС, Python, Ollama | админ |
| 2–4 | скачать модели, `install.sh` / `install.bat`, `backend.smoke` | админ |
| 4–5 | открыть порт, включить `RECTOR_REQUIRE_LOGIN`, проверить с другой машины | админ |
| 5–6 | раздать пароли подразделениям, удалить файл паролей | админ |
| 6–8 | загрузить реальные документы (10–20 файлов), проверить карточки и публикацию | подразделения |
| 8–10 | прогнать 10–15 реальных вопросов ассистенту, записать, где отвечает плохо | ректорат |
| 10–12 | настроить автозапуск, бэкап по расписанию, проверить перезагрузку | админ |
| 12–14 | обучение сотрудников: вход, загрузка, проверка, публикация | админ |
| 14–16 | доработки по итогам вопросов (модель крупнее, пороги поиска) | разработчик |
| 16–18 | повторная проверка `backend.smoke --ask`, приёмка | админ |
| 18–20 | резерв: непредвиденное | все |

Критический путь — скачивание моделей и первый прогон индексации.
Всё остальное можно делать параллельно.
