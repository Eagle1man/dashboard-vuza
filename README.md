# Дашборд ректора — локальная система вопросов по документам

Южный университет (ИУБиП) / Southern University (IMBL).
Работает целиком на компьютере, без интернета и без облачных сервисов.

---

## Что это

Дашборд с управленческой аналитикой и ИИ-ассистент, который отвечает
на вопросы **по документам университета** — положениям, протоколам,
приказам, отчётам — и показывает, из каких документов взят каждый ответ.

Два режима работы, и их важно не путать:

| Что | Откуда данные | Статус |
|---|---|---|
| Цифры в ленте показателей | сгенерированы для примера | **демонстрационные** |
| Ответы ИИ и список источников | реальные файлы из `knowledge/` | **настоящие** |

Демо-цифры помечены в подвале и в системном промпте модели: если речь
о показателе с дашборда, ассистент прямо говорит, что цифра демонстрационная.
Это сделано намеренно — иначе реальная цитата из протокола стоит рядом
с выдуманным процентом и выглядит как одно и то же число.

## Быстрый старт

```
1. Двойной клик по install.bat     один раз, 3–5 минут
2. Двойной клик по start.bat       запуск
3. Открыть в Ollama нужную модель  см. раздел «Что сделать, если ИИ молчит»
```

Дашборд откроется на `http://127.0.0.1:8765/`.

> Открывать `web/index.html` двойным кликом можно — дашборд покажет
> демо-цифры, но ИИ не заработает: браузер из режима `file://` не пускает
> страницу обращаться к локальному серверу. Правильный способ — `start.bat`.

### Как добавить документы

1. Положить файлы (PDF, DOCX, XLSX, MD, TXT, HTML) в папку `knowledge/`.
2. Запустить `start.bat` — новые файлы проиндексируются автоматически.

Папка `knowledge/demo/` — примерные документы для проверки работы.
Они помечены меткой «демо» в списке источников. Реальные файлы кладутся
рядом, в корень `knowledge/` или в подпапку с названием подразделения.

### Резервная копия

`backup.bat` — копирует `data/dashboard.db` в `data/backup/`, хранит 30 копий.
Вся система — один файл, копия файла и есть копия системы.

## Что где лежит

```
data/dashboard.db      всё состояние: цифры, документы, векторы, история
knowledge/             документы для поиска (ваши файлы)
web/                   интерфейс (HTML/CSS/JS, без сборки)
backend/               сервер, поиск, ИИ
logs/                  журналы
```

### Устройство базы

Один файл SQLite, четыре слоя:

| Слой | Таблицы | Зачем |
|---|---|---|
| Справочники | `dim_metric`, `metric_alias`, `dim_org`, `dim_period` | что измеряем, как это ещё называется |
| Витрина | `fact_metric`, `fact_detail` | цифры по периодам и подразделениям |
| Корпус | `doc`, `doc_chunk`, `chunk_fts`, `chunk_vec` | документы, куски, полнотекст, векторы |
| Журнал | `ask_log`, `meta` | история вопросов, настройки |

**Почему SQLite, а не PostgreSQL.** База на 34 метрики и сотни документов
не требует отдельной службы, пользователя, пароля и обновлений. Один файл
копируется на флешку — это и есть резервная копия. Полнотекстовый поиск
(FTS5) входит в SQLite, поэтому вторую базу ставить не нужно.

**Почему векторы хранятся в том же файле.** При корпусе вуза
(5–9 тысяч кусков) полный перебор косинуса занимает единицы миллисекунд,
поэтому отдельный векторный сервер не нужен. Он понадобится, только
если корпус вырастет до десятков тысяч кусков.

## Как работает поиск

Вопрос проходит три стадии:

1. **По словам** (FTS5). Название, заголовок и текст куска. Запрос
   стеммируется по-русски: «отсев» находит «отчисления».
2. **По смыслу** (векторы). Вопрос кодируется той же моделью, что и
   документы, и сравнивается с кусками.
3. **Слияние RRF** + переранжирование. Результаты двух каналов
   объединяются по рангам, затем пересортировываются по тому, какая
   доля вопроса попала в название документа, заголовок и текст.

Три решения, без которых качество падает:

- **Каналы обрезаются до одинаковой длины до слияния.** Иначе канал,
  вернувший больше записей, выигрывает сам по себе за счёт количества
  и топит точные совпадения другого.
- **Канал-вектор отключается, если модель не скачана.** Эмбеддинг-заглушка
  не несёт смысла; если дать ему половину веса, он перемешает выдачу.
  Система пишет об этом в `/api/health` и в ответе — молча деградировать
  нельзя.
- **Совпадение в названии важнее совпадения в абзаце.** На вопрос про
  аттестацию регламент об отчислениях выигрывал за счёт слов
  «аттестация» и «преподаватель», хотя правильный документ содержал
  только первое — зато в самом названии.

## Что делать, если ИИ молчит

Ассистент всегда объясняет, что с ним не так. Три частые причины:

**`Ollama не отвечает`** — не установлена или не запущена.
Установите с <https://ollama.com>, затем запустите `start.bat`.

**`модель ... не скачана`** — выполните в терминале:
```
ollama pull qwen2.5:1.5b
ollama pull nomic-embed-text
```
Модель выбирается автоматически под ваш компьютер, `install.bat`
печатает, какая именно.

**`векторы в аварийном режиме`** — корпус проиндексирован с заглушкой
(например, при первой установке без интернета). После скачивания
модели пересоберите индекс:
```
.venv\Scripts\python.exe -m backend.ingest --force
```
До этого поиск работает только по словам — это заметно хуже, но
работает.

## Разработчику

### Проверки

```
python -m backend.tests.test_seed_matches_js   демо-цифры совпадают с браузером
python -m backend.tests.test_retrieval         поиск находит нужный документ
```

Первый тест сверяет вывод Python с реальным выводом Node по `data.js`:
обе реализации детерминированного генератора обязаны давать одни и те же
числа, иначе экран и база покажут разное.

Второй тест проверяет не «поиск что-то вернул», а попадание нужного
документа — иначе он был бы зелёным и при неверной выдаче.

### Полезные команды

```
python -m backend.autoconfig      определить модель по железу
python -m backend.ingest --force  переиндексировать всё
python -m backend.ingest --prune  убрать из индекса удалённые файлы
python -m backend.modelcheck      проверить готовность модели
python -m backend.app             запустить сервер
```

### API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | состояние: база, индекс, модель, железо |
| GET | `/api/metrics` | витрина показателей |
| GET | `/api/docs` | список проиндексированных документов |
| GET | `/api/asklog` | последние вопросы |
| POST | `/api/ask` | вопрос → ответ со ссылками на источники |
| POST | `/api/reindex` | переиндексация папки `knowledge` |

## Ограничения, о которых надо знать

- **Цифры ленты демонстрационные.** Подключение реальных данных —
  это загрузчик в `fact_metric`; интерфейс менять не придётся.
- **Персональные данные.** В демо-режиме drill-down показывает
  вымышленные ФИО. При загрузке настоящих данных персональные данные
  нельзя класть в базу без обезличивания (152-ФЗ): для этого в
  `fact_detail` заведена колонка `subject_hash`.
- **Репозиторий должен быть приватным** — в `knowledge/` попадают
  положения и протоколы вуза.
- **Модель скачивается один раз при установке** — нужен интернет.
  Если на компьютере ректора интернета нет, модель переносится
  файлом с машины, где есть.
